00

시작부터 마무리까지, 이렇게 일합니다

판단은 제가, 정리와 구현은 AI가. 여섯 단계를 거치며 무엇을 누가 하는지 나눠 둡니다.

  1. 01

    BRIEF

    판 짜기

    목표 · 범위 · 하지 말 것을 먼저 정해요.

    내가
    번호를 붙인 요청 목록과 제약을 정리
    AI가
    빠진 항목이 없는지 체크리스트로 되묻기

    OUTPUT요청 목록 · 제약 조건

    “1. 문구 변경 2. 여백 축소 3. 온보딩 추가… 내용은 수정하지 마.”
  2. 02

    CONTEXT

    자료 넣기

    근거는 말로 설명하지 않고 원본을 직접 줘요.

    내가
    이력서 · 자기소개서 · 기획서 PDF · 화면설계서 첨부
    AI가
    긴 문서를 읽고 구조 · 수치를 뽑아 정리

    OUTPUT원본 자료 묶음

    “이 PDF들이 프로젝트 원본이야. 정보구조도 · AS-IS · TO-BE가 잘 보이게.”
  3. 03

    STRUCTURE

    구조 정하기

    무엇을 보여주고 덜어낼지는 제가 정해요.

    내가
    정보구조 · 화면 순서 · 메인 프로젝트 3개 결정
    AI가
    정한 구조대로 데이터 파일과 섹션 틀 만들기

    OUTPUT정보구조 · 화면설계서

    “메인은 HAELON · 위버스 · 성수 세 개. 나머지는 전체 프로젝트로.”
  4. 04

    BUILD

    만들기

    한 번에 한 화면, 한 가지 변경만 요청해요.

    내가
    우선순위와 순서 지정
    AI가
    Claude Code로 HTML · CSS · JS 구현

    OUTPUT실제로 열리는 화면

    “가로형 키오스크가 메인이야. 직접 눌러 볼 수 있게 넣어줘.”
  5. 05

    REVIEW

    보고 고치기

    실제 화면을 보고, 느낌이 아니라 구체적으로 짚어요.

    내가
    행간 · 자간 · 여백 · 색 · 잘림을 눈으로 확인
    AI가
    지적한 곳만 작게 수정, 스크린샷으로 보고

    OUTPUT수정 기록

    “썸네일 왼쪽이 다 잘려.” → 칸 비율을 16:9로
  6. 06

    SHIP

    검증 · 공개

    “됐다”는 말 대신 확인한 근거를 받아요.

    내가
    최종 판단 · 사실 확인 · 공개 여부 결정
    AI가
    모바일 넘침 · 깨진 이미지 점검, 원본과 글자 대조, 실제 주소 확인

    OUTPUT배포된 사이트

    “이력서 내용은 바꾸지 마.” → 원본과 글자 대조로 확인

01

단계마다 역할을 나눕니다

내가 하는 일

목표 · 범위 · 일정 · 산출물을 먼저 정합니다. 무엇을 확인해야 하는지가 정해져야 AI에게 줄 질문도 정해집니다.

AI에게 맡기는 일

정해진 범위 안에서 체크리스트 · 목차 · 일정표 초안. 빠진 항목이 없는지 반대로 질문하게 합니다.

MODELOpus — 짧은 정리와 반복 수정

내가 하는 일

설문 설계, 현장 관찰, 출처 확인. 숫자는 원문에서 직접 확인하고, 문제를 다시 정의하는 판단은 제가 내립니다.

AI에게 맡기는 일

모은 자료의 분류 · 요약 · 비교표. 출처 없는 문장은 쓰지 않도록 조건을 걸고, 근거 문장을 함께 표시하게 합니다.

MODELFable — 긴 자료를 한 번에 읽고 구조화

내가 하는 일

정보구조도 · 화면설계서 · 문구. 화면에 무엇을 남기고 무엇을 덜어낼지 정합니다.

AI에게 맡기는 일

설계서대로의 HTML · CSS 구현, 문서 조판, 반복 작업. 한 번에 한 화면 · 한 가지 변경만 요청합니다.

MODELFable — 구조 설계 · 큰 구현 / Opus — 작은 수정

내가 하는 일

실제 화면을 직접 보고 어색한 곳을 짚습니다. 최종 결정과 사실 확인은 넘기지 않습니다.

AI에게 맡기는 일

스크린샷 · 오류 · 가로 넘침 자동 점검, 원본 문서와 글자 대조. "됐다"는 말 대신 확인한 근거를 보고하게 합니다.

MODELOpus — 체크리스트 대조

02

프롬프트는 짧게, 조건은 분명하게

포트폴리오 사이트 예쁘게 만들어줘.
[목표]  메인 '나의 이력'을 1920×1080 한 화면에 사진 · 경력이 다 보이게.
[맥락]  첨부한 화면설계서 p.12, 현재 사이트 링크.
[제약]  내용 수정 금지 · 일러스트 금지 · 폰트는 Pretendard / Orbitron만.
[출력]  바뀐 부분만, 이전으로 되돌릴 수 있게.
[검증]  1920×1080 스크린샷과 모바일 가로 넘침 여부를 함께 보고.
  • GOAL무엇이 끝인지 한 문장
  • CONTEXT근거 자료를 직접 첨부
  • LIMIT하지 말 것을 먼저
  • OUTPUT바뀐 부분만, 되돌릴 수 있게
  • CHECK확인 방법까지 요청

03

토큰은 아껴서, 필요한 곳에

  1. 01

    작게 쪼개기

    한 번에 하나의 화면, 하나의 변경. 긴 요청은 번호를 붙여 순서대로.

  2. 02

    모델 나눠 쓰기

    설계 · 대량 정리는 Fable, 문구 · 간격 같은 작은 수정은 Opus.

  3. 03

    다시 쓰지 않기

    전체 재작성 대신 바뀐 부분만. 결과물은 파일로 받고 대화에 붙여 넣지 않습니다.

  4. 04

    맥락은 문서로

    화면설계서 · 데이터 파일을 기준점으로 두고, 대화가 길어지면 요약 후 새로 시작합니다.

04

이 웹사이트도 이렇게 만들었습니다

  1. STEP 1

    기획은 직접

    정보구조도 · 화면설계서를 먼저 쓰고, 그 문서를 AI 작업의 기준으로 넘겼습니다.

  2. STEP 2

    구현은 Claude Code

    HTML · CSS · JS를 화면 단위로 구현하고, 데이터는 한 파일로 모아 문구를 한곳에서 고칩니다.

  3. STEP 3

    피드백은 화면으로

    실제 화면을 보고 행간 · 여백 · 색처럼 구체적으로 짚어 수십 번의 작은 수정을 반복했습니다.

  4. STEP 4

    배포와 검증

    GitHub Pages에 올린 뒤 실제 주소에서 다시 확인. 이력서 PDF는 원본과 글자를 대조해 내용이 바뀌지 않았음을 확인했습니다.

05

AI에게 맡기지 않는 것

  • 숫자와 출처의 사실 확인
  • 무엇을 남기고 덜어낼지의 결정
  • 개인정보와 팀원의 기여 표기
